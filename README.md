# 結 YUI · 团队任务板

独立的本地完整应用：HTML/CSS/JavaScript 界面 + Flask 后端 + SQLite 数据库。
发布任务、认领、提交、退回、验收、讨论和勋章都是真实操作，会保存到数据库。
任务分两种：**小任务**一个人认领、一个人做完；**大任务**好几个人加入、一起做完，发布者自己也能一起做。

## 部署到服务器

用 Docker 部署到服务器的做法见 [云端部署](deploy/README.md)。账号、邀请码和数据库不随源码发布。

## 获取与源码运行

GitHub Releases 里的 v1.0.0、v1.1.0 是旧版界面（当时叫「搭把手」）。现在的版本从源码运行；需要离线运行包时用 `python scripts/build_release.py` 自己打一个。
旧版的数据库可以直接拿来用：启动时自动升级，任务、账号、勋章都保留，旧分类变成标签，v1.1.0 的「有帮助」变成鼓掌。

Git 仓库保留源码、数据库结构和生成脚本，不上传使用中的数据库、账号密钥或设计参考截图。直接从源码运行：

```bash
python -m venv .venv
# Windows: .venv\Scripts\python.exe；macOS/Linux: .venv/bin/python
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py demo
.venv/bin/python run.py
```

上面三条 Python 命令应使用虚拟环境的解释器；`demo` 只用于空数据库，可省略并自行注册账号。

## 解压后启动

### Windows

1. 安装 Python 3.10 或更新版本（若已安装可跳过）。
2. **完整解压 ZIP**，进入 `bounty-platform-local` 文件夹。
3. 双击 `start.bat`。浏览器会打开 `http://127.0.0.1:5080`。
4. 保持命令行窗口开启；关闭窗口或按 Ctrl+C 停止，数据仍保留。

发布包已包含纯 Python 依赖，不需要运行 pip、npm，不需要安装 MySQL，也不需要联网下载网页资源。
没有打包 Python 解释器，因此电脑必须先有 Python。

### macOS / Linux

```bash
cd bounty-platform-local
python3 run.py
# 或：sh start.sh
```

也可以使用 `python run.py --port 5081` 改端口，或加 `--no-browser` 只启动服务。
默认只监听 `127.0.0.1`，不会对局域网或公网开放。没有配置后台常驻或开机自启。

### 给团队一起用

在一台大家都能访问的机器上用 `--host` 指定监听地址，队友用浏览器打开 `http://<这台机器的地址>:5080` 即可：

```bash
python run.py --host 0.0.0.0 --port 5080 --data-dir team-data --no-browser
```

只在可信的团队网络里这样做：能访问这个地址的人都能看到登录页。应用本身走 HTTP；需要放到公网时，请在前面加一层带 HTTPS 的反向代理。
页面上的时间按**每个人浏览器所在的时区**显示，队友不在同一个地方也各看各的当地时间；发布任务时填的截止时间也按发布者当地时间理解。
环境变量 `BOUNTY_TZ_OFFSET`（小时数，默认 8 即北京时间）只管两件事：浏览器没报时区时的兜底，以及全队共用的「本周」从哪天零点算起（每周团队收集包）。
在 Windows 上需要 `pip install -r requirements.txt` 装上 `tzdata`，否则所有人都按 `BOUNTY_TZ_OFFSET` 显示。

### 团队共同维护标签表

mission 不分管理员和普通成员。登录后的成员都可以打开「标签管理」，添加说明、调顺序、改名、合并或拿掉标签。已有任务上的标签仍会保留。账号停用、密码重置和团队邀请码由统一账号管理端维护，不在 mission 再设一套权限。

### 生产统一账号

生产入口为 `wsgi:create_cloud_app()`，使用独立的公共账号库，和计算平台共用注册、密码与登录会话。两平台直接访问这个库，不互调业务 API，不复制密码，不挂载对方的业务库。具体安装与成对切换见 [deploy/README.md](deploy/README.md)。

源码本地运行仍可使用独立演示数据；已经迁入统一账号的数据目录必须配置 `TEAM_ACCOUNTS_DATABASE`，缺失时启动失败，防止意外启用第二套本地账号。

2. 认领人在「发现」最上面点几个方向，「按你选的方向」那一排马上换；从推荐里直接认领，进入详情提交成果。

来不及做完时，做的人可以填新截止时间和理由申请延期，验收人同意后才生效；验收人也能直接延期，已截止、没人接的任务延后就又能接了。
小任务、大任务和拆出来的分工都能延期；大任务延期不改各份分工的截止时间，勋章和经验也照旧。

不同账号若使用同一浏览器会话，需要先退出再切换。

## 实现范围

- 独立注册、密码哈希、登录、退出和会话保存。
- **发现**：最上面是方向条，就是团队的标签表（带管理员写的说明），每次进来都能重新点想做的方向，点完不用保存，也不用自己输入。下面是两排互不重复的推荐：
  - 「按你选的方向」只看这次选的方向，几张卡轮流照顾到每个方向，改方向时这一排当场重新发牌；
  - 「按你做过的」只看自己的经历（做完过的标签、参与过的项目、和做过的任务内容相似），标题旁列出你常做的标签；还没做过任务时换成好上手、能拿新勋章的任务。
  每张卡写明理由，可以「换一批」或「不感兴趣」（都不刷新页面）。推荐全部由数据实时算出，不写死任何分类，新项目、新标签会自动出现在方向条和推荐里。
- 发布任务时从团队的标签表里挑标签，表里没有的可以写新的（自动加进表）；项目可以随手新建；按标签、项目、预计投入（半天内 / 一两天 / 一周左右）、关键词和「只看能拿新勋章的」筛选；每页 12 个任务。
- **大任务**：要好几个人一起才能做完的事。发布时和小任务填的一样，再选想要几个人（或不限），可以勾「我也一起做」。
  - 想做的人点「加入」（不是认领），人够了就不再招人；发布者自己也能加入。一起做的任何一个人都能提交成果，交上去之前可以退出。
  - 发布者验收时勾选这次给谁发勋章，默认一起做的每个人，没出力的可以不勾；发布者自己也在里面时，至少还要发给一个别人。每个人拿到同一种勋章和同样多的经验（分量按每个人的投入算），颁奖时写着和谁一起完成的。
  - 分工不用一开始就拆好：做着做着发现要分头干，一起做的人（或发布者）随时可以拆出一份分工。分工就是普通的小任务，出现在「发现」里，卡片上写着属于哪个大任务，谁都能接；接下的人单独拿一枚勋章，也就加入了大任务。拆分工的人验收它，大任务的发布者也能验收。拆出去的分工还在做时，大任务先不能交；没人接的分工在大任务验收后变回普通小任务。
  - 首页有一排大任务（你在里面的、你发布的排前面，然后是还能加入的），卡片上用头像和虚线空位表示几个人在做、还缺几个人；「大任务」页列出全部；一起做的大任务也算「轮到你」。
- **我的任务**：按「轮到你 → 等对方 → 没人认领 → 已完成」分组，每行写明最近一条动态。
- 发布者不能认领自己任务；并发认领只允许一人成功。
- 小任务只有认领人可提交，大任务一起做的人都能提交；只有发布者（大任务拆出来的分工，大任务的发布者也行）可验收或退回，退回必须说明原因；验收时可以选一句夸奖。
- 任务讨论与交付历史持续保留；用户内容按安全文本处理。
- **两条成长线一起涨**：等级按工作量给经验（轻量 10、常规 30、重要 80，加急 +50%），啃硬骨头的人升得快；勋章「点・线・面」× 急不急共 6 种，凑齐一行有庆祝。
- 验收与勋章发放在同一个事务中完成，每个任务只发一次；认领人下次打开「成就」时播放颁奖，按稀有度分档，可跳过。
- **勋章柜**：「成就」页最上面，六种勋章各占一格，拿到几枚就叠几层，没拿到的是剪影并写着现在有几个任务能拿。点一枚拿起来看：勋章转着飞到深色展台中央，可以拖着转、点一下翻面，背面刻着最近一句夸奖；旁边列出每一次获得，左右键换下一枚，Esc 放回去。发现页的等级卡上也有一排迷你勋章柜。
- **冷门任务**：发布超过 5 天没人接的任务卡上贴「冷门 +20%」，推荐里也会往前放；接下它的人完成后经验多 20%。
- **新人第一单**：认领人还没有任何勋章时，发布者验收页会提示「这是 TA 的第一个任务」；第一枚勋章颁奖时盖一个「初」字，勋章柜里也留着这个标记。
- **鼓掌的回声**：自己完成的任务又被队友鼓掌时，下次打开「发现」会看到一张纸条（看过就收起来）。
- **称号**：14 个称号看「怎么帮忙」而不是「帮了多少」，例如救火队员（3 个加急）、无名英雄（3 个冷门）、跨界选手（3 个项目）、领路人（你发布的任务成了 2 个人的第一枚勋章）、并肩作战（和队友一起完成 2 个大任务）、挑大梁（你发布的大任务被大家一起做完了）。全部从已有记录算出来；没解锁的显示问号、条件和进度，解锁后像勋章一样进信箱、在颁奖里盖章，可以盖到名牌上。
- **全收集**：六种勋章集齐时颁奖有专门的一档，名牌换金边，勋章柜亮起来。
- 名牌（等级、称号印章、最多三枚勋章，可以存成图片）、团队名牌墙、团队动态和鼓掌、每周团队收集包。
- **学期绘卷**：按春季（2–7 月）/ 秋季（8–1 月）学期，一屏一屏讲这学期：完成了几个、升了几级、多了哪些勋章、帮了谁、一起完成了哪些大任务、最常做的方向、最重的一个任务、队友说过的话、解锁的称号、团队的总数；最后可以存成一张图。学期最后三周首页会贴一张纸条提醒。
- **縁側**（游戏角）：全都随便玩，不花任何东西。勋章就是钥匙，解锁了就一直在：
  - **积木**：16×16 的板子上一层层往上搭，斜着看的立体视角，可以往左右转着看四个方向。零件落在下面最高的地方：点到哪个零件的顶面就叠上去，点到侧面就放在它跟前；拖走或删掉一个零件，压在它上面的会掉下来。零件分点（圆钉、球、圆顶、圆柱、尖顶）、线（梁、柱子、台阶、栏杆、拱门）、面（方块、平板、斜坡、屋顶、圆角）三类，一开始有圆钉、短梁、方块和墨、白、米三种颜色；拿到哪种勋章就多一种它的颜色（点绿、线青、面蓝，带「急」的是黄、橙、红，一共 5 枚勋章多一个木色，集齐六种多一个金色），点 / 线 / 面勋章越多，对应的零件越多，拿到的勋章本身也能立在板子上；一起完成一个大任务多一个「双环」零件。作品可以存好几件，挑一件挂到名牌上，队友在团队名牌墙和游戏角的积木墙上都能看到（按保存时的视角）；名牌存图时也会带上它。保存时服务器检查零件和颜色都已解锁、都在板子里、没有堆过 24 层，并按同样的规则让零件落好。以前平面板子上的作品升级时自动换成立体零件，摆在原来的位置。
  - **一笔画**：每天零点程序按日期出一套新的 6 关，全队同一套，一关比一关难（点阵变大、线变多、岔路口变多），画完一关开下一关，最近 7 天的都还能补；另有 15 关入门，前三关直接开；一共拿到 3 枚勋章后开放「随机一笔」，无限出题。每道题都是一次随机游走的轨迹，保证画得出来；笔画都由服务器检查。
  - **盖章挑战**：随便玩几局。拿到「急」勋章开「加急日」，拿到「面」勋章开「期末周」（45 秒）；印章样式「好」「赞」「点线面」和称号印章也靠勋章开。服务器记录开始时间并检查分数上限；连着玩很多局时结算页会轻轻提醒一句。
  - 颁奖时每枚勋章会说出它在縁側解锁了什么；有新解锁时导航上的「縁側」亮一个「新」。
  - 游戏不给经验也不给勋章，只能解锁「一笔成形」「稳如老章」两个称号；没有排行榜。
- 动效开关、系统减少动态效果支持；音效用 Web Audio 现场合成，默认关闭；关闭 JavaScript 后仍可通过普通页面完成业务流程。

奖励是荣誉勋章，不含金额、积分兑换、支付或结算。
成果支持文字和链接，**不含文件附件上传**。首版不含邮件通知、任务编辑/取消/转派、找回密码和管理员后台。

时间在数据库里按 UTC 保存，界面上按看的人自己的时区显示（见上文「给团队一起用」）。倒计时按小时算，不说「今天」，免得不同时区的人理解成不同的一天。
截止后禁止新认领，已经认领的任务仍可提交和验收。

## 数据库、备份与全新使用

数据库为 `instance/bounty.sqlite3`；登录密钥首次启动创建于 `instance/secret.key`。
重启应用不会重置用户、任务、讨论或勋章。数据库结构见 `database/schema.sql`。

直接使用全新数据目录（不会改变演示库）：

```bash
python run.py --data-dir my-data
```

初始化空数据库或向空目录导入演示任务：

```bash
python manage.py --data-dir my-data init
python manage.py --data-dir another-demo demo
```

演示导入只允许写入空数据库，避免覆盖已有内容。

一致性备份（服务运行时也可执行，不覆盖同名文件）：

```bash
python manage.py backup backups/bounty-20261014.sqlite3
# 自定义数据目录：
python manage.py --data-dir my-data backup backups/my-data.sqlite3
```

旧数据清理：每天第一个请求会顺手清一次已经用不上的记录，也可以手动执行 `python manage.py cleanup`。任务（包括过期没人接的）、勋章、讨论、称号和积木作品都不会动；清掉的是：
- 盖章挑战里开了没打完的局（一天后）；30 天前的成绩只留每人每种玩法的最高分、最长连击和每学期最高分。
- 一笔画每天的关卡过了能补画的 7 天后，记录合成每人每学期画完了几关（称号和学期绘卷照常算）。
- 已经完成或过了截止时间的任务上的「不感兴趣」。

恢复：停止服务，将备份复制为目标数据目录的 `bounty.sqlite3`。务必先保留目标目录旧数据；不建议将备份直接覆盖到仍运行的数据库。
也可以停服务后备份整个数据目录。若 `secret.key` 缺失，用户需重新登录，账号和任务仍在。

## 代码结构

- `run.py` / `start.bat` / `start.sh`：跨平台本地启动入口。
- `app.py`：页面路由、认证和会话，使用服务器端身份校验。
- `bounty/db.py`：表结构、事务与旧版数据迁移。
- `bounty/service.py`：任务归属、状态流转、标签、鼓掌及输入校验。
- `bounty/honors.py`：六种勋章「点・线・面」。
- `bounty/teams.py`：大任务的拆分工，以及一起做的人、拆出来的分工、大任务列表、一起完成的记录这些查询（加入、提交、验收在 `service.py`）。
- `bounty/discover.py`：推荐打分、团队动态、我的任务分组等只读查询。
- `bounty/progress.py`：经验和等级、勋章凑齐一行、团队收集包。
- `bounty/titles.py`：称号的解锁条件和进度。
- `bounty/tags.py`：团队的标签表和管理员操作。
- `bounty/unlocks.py`：勋章在縁側解锁什么（积木颜色和零件、游戏玩法、印章样式）。
- `bounty/blocks.py`：积木零件的尺寸、重力、作品的检查和存取，以及平面作品的升级。
- `bounty/cleanup.py`：每天一次的旧数据清理。
- `bounty/games.py`：一笔画的入门关卡、每天按日期出的 6 关、随机出题、笔画检查，盖章挑战的成绩检查。
- `bounty/recap.py`：学期划分和学期绘卷的统计。
- `bounty/demo.py`：独立演示数据生成器。
- `templates/`、`static/`：完整界面。`ui.js` 管手感、音效和颁奖；`board.js` 管方向条、两排推荐、任务墙翻页和发布页预览；`case.js` 管勋章柜和拿起来看；`iso.js` 把积木画成立体的（作品缩略图、零件小图和编辑器共用），`blocks.js` 是积木编辑器；`games.js` 是两个小游戏；`share.js` 管存成图片和学期绘卷的翻页。
- `manage.py`：数据库初始化、演示导入、旧数据清理和备份。
- `vendor/`：发布包内附的运行依赖及其许可证。
- `tests/`：后端流程、权限、冲突、持久化、推荐、经验和颁奖测试。

没有独立前端构建步骤，不需要额外启动一个前端服务器。
任务、讨论、勋章等业务数据独立；生产认证依赖公共 team-accounts 包和账号库，不依赖另一业务平台的进程或数据接口。

## 验证与开发

发布包内运行测试：

```bash
python -c "import run,unittest; result=unittest.TextTestRunner(verbosity=2).run(unittest.defaultTestLoader.discover('tests')); raise SystemExit(not result.wasSuccessful())"
```

源码目录没有 `vendor/` 时，可执行 `python -m pip install -r requirements.txt` 安装依赖。
可选浏览器测试 `python scripts/check_motion.py` 需要额外安装 `websocket-client` 和 Chromium；与普通使用无关。
验证范围及发布信息见 `RELEASE_NOTES.txt`。Windows 启动脚本已提供，尚未在原生 Windows Python 环境实机执行。
